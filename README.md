# 假人盾构机 1.6.0

**AI 声明：本项目完全由 OpenAI Codex 开发。**

[English](README.en.md)

Minecraft Java 版 26.3 Fabric 客户端模组，通过服务端 Carpet `/player` 命令，让有限名字的假人依次处理水平矩形内的方块。

## 安装

将 `build/libs/fake-player-tbm-1.6.0.jar` 放入 26.3 Fabric 实例的 `mods` 文件夹，删除旧版，同时安装 Fabric API。需要 Fabric Loader 0.19.5 或更高版本和 Java 25。

服务端（单人世界即本地服务端）必须安装支持 26.3 的 Carpet，且玩家有权限使用 `/player`。在线模式服务器可能要求名字对应真实账号，或由管理员开启 `allowSpawningOfflinePlayers`；白名单和玩家数量限制等也可能阻止召唤。请先手动测试 `/player TBM_1 spawn` 和 `/player TBM_1 kill`。整个任务期间请保留名字池，避免其他玩家或任务使用相同名字。

## 图形界面

在聊天栏输入 `/faketbm` 或 `/faketbm gui` 打开界面，填写两个角的 X/Z、向下搜索的起始 Y 高度、名字前缀、假人数量、每次工作的秒数及命令间隔，然后选择“保存并开始”。“停止”停止分配新位置并清理已召唤的假人。运行中可以修改间隔并点击“应用间隔”。界面底部的进度条显示当前区域已确认完成的列数。

例如 X1=0、Z1=0、X2=9、Z2=4、起始 Y=64，前缀 `TBM_`、数量 3、时间 30，表示依次处理 50 个坐标，用 `TBM_1` 至 `TBM_3` 三个名字，每次持续攻击 30 秒。范围两端都包含。Minecraft 水平轴是 X/Z，Y 是向下搜索的起始高度。客户端从该 Y 开始逐格向下穿过空气；遇到的第一个非空气方块若为完整碰撞方块，且其上两格都是空气，就在该方块上方生成假人。不会穿过该方块继续搜索地下洞穴。

也可使用命令：

```text
/faketbm area 0 0 9 4 64
/faketbm config TBM_ 3 30
/faketbm interval 20
/faketbm start
/faketbm status
/faketbm stop
/faketbm resume
```

名字前缀只能含英文字母、数字和下划线，完整名字最多 16 字符；数量为 1–100，秒数为 1–86400。只有在目标列中观察到假人脚下的底部基岩时，该列才记为完成；单纯计时结束不会增加进度。未确认完成的列会在一轮结束后继续处理，已完成的列会被跳过。全部确认完成且假人清理完毕后任务结束。

进度和上次使用的区域、名字池、工作时长、间隔保存在客户端 `config` 目录。重启客户端并进入原世界后，打开界面选择“保存并开始”，即可使用上次设置继续。完成记录按世界、维度、搜索起始 Y 和列坐标区分；单人世界使用存档路径区分，多人服务器使用服务器地址区分。如果同一服务器地址更换了世界，必须先清除旧进度。配置目录中的进度文件名是世界和维度标识的哈希。

如需重新处理某个区域，先停止任务，设置该区域和搜索 Y，然后执行 `/faketbm clear`。此命令会清除当前世界和维度下该区域、该 Y 的完成记录。

## 自动恢复和限制

- 客户端能看到假人位于其目标列、且脚下是维度最低 5 层内的基岩时，记录该列已完成并提前发送 `/player 名字 kill`；假人下线后复用名字。检测遵守命令发送间隔；假人或区块不在客户端加载范围内时无法探测，仍会按原定时间清理。

- 目标区块必须在客户端加载；未加载、列中没有方块、第一个非空气方块不具备完整碰撞体或头顶两格不是空气时，该位置等待并指数退避后重新检查。请靠近区域使区块加载；区块状态或地形变化需要等到下次检查。
- 假人上线后依次发送潜行、向下看和持续攻击命令。潜行可以避免走出边缘，但无法阻止脚下方块被挖掉后的坠落，也不保证避免其他伤害。客户端看到的方块信息可能滞后于服务器。

- 假人死亡或提前离线时，保留其当前位置，使用同一名字指数退避重试；召唤未上线、偏移位置或清理未下线也采用指数退避，其他假人继续处理。每个位置独立计数：召唤失败或死亡后的等待依次为 5、10、20、40 秒等，最多 300 秒；处理完成并分配新位置后重置。召唤会先等待 20 秒确认上线，再开始退避。清理命令有独立计数，首次等待 20 秒，之后翻倍，最多 300 秒。上述时间按客户端 20 tick/秒换算。在线但不属于当前任务的名字会等待释放。指令没有权限或名字不能生成时会一直重试，请查看服务端反馈。
- 假人实体在客户端可见时，若其水平位置偏离目标中心超过 1.5 格，会尝试清理并重新处理该位置。远处或其他维度实体未加载时无法检测其位置，模组不会将不可见视作离线；上下坠落不触发偏移重试。
- 玩家切换维度时，新召唤暂停，切回任务所在维度后继续；已在线假人的控制和清理仍会尝试执行。断线后，在同一客户端进程内重连原服务器，再按“确认原服后恢复”或执行 `/faketbm resume`。程序会核对单人存档路径或多人服务器地址，但无法识别同一地址下替换的世界。关闭客户端后运行中的假人状态不保留；重新进入原世界后用保存的设置重新开始，已确认的列仍会跳过。假人可能需要手动清理。
- 客户端必须保持在线才能调度。断线、游戏退出或服务器拒绝指令时无法保证清理；需要时手动执行 `/player 名字 kill`。停止期间尚未确认上线的召唤超时后会放弃等待；异常延迟才上线的假人可能需要手动清理。
- 命令间隔可设置为 1–1200 客户端 tick，默认 20；运行中也可通过 `/faketbm interval 数值` 修改。模组最多每个客户端 tick 发送一条命令。原版没有固定的最小命令间隔，服务器使用可配置的刷屏计数；在默认规则下非豁免玩家长期快于每 20 个服务器 tick 一条可能被踢出。服务器卡顿、其他命令、插件和自定义规则也会影响限制；1 tick 不保证安全。持续时间使用客户端 tick，不保证与实际服务器时间一致；服务端延迟或拒绝命令可能影响效果。假人游戏模式由 Carpet 默认行为决定。本模组不提供工具，也不会逐个验证方块是否已经被挖掉。进度文件写入失败时，结果暂存在内存并定期重试；若此时关闭客户端，未写入的进度可能丢失。

## 构建和测试

先设置 `MC_DIR` 环境变量，指向 Minecraft 游戏目录，再运行 `./build.sh`。脚本需要 JDK 25，以及 `versions/26.3-Fabric/26.3-Fabric.jar`、`versions/26.3-Fabric/mods/fabric-api-0.160.5+26.3.jar` 和该目录下的游戏依赖。`./test.sh` 使用模拟连接测试调度，不替代游戏内测试。

命令参考：[Carpet 官方命令文档](https://github.com/gnembon/fabric-carpet/wiki/Commands)；工具链参考：[Fabric 26.3 发布说明](https://fabricmc.net/2026/09/15/263.html)。
